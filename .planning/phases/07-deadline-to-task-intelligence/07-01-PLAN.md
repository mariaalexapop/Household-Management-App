# Plan 07-01: Suggestions schema + migration

**Wave:** 1 (no dependencies)
**Decisions:** D-03, D-05, D-08

## Goal
Create the `suggestions` database table to persist deadline-generated task suggestions with status tracking.

## Tasks

### 1. Add suggestions table to Drizzle schema
**File:** `src/lib/db/schema.ts`

Add a `suggestions` table with columns:
- `id` — UUID primary key (default gen_random_uuid)
- `householdId` — FK to households.id (not null)
- `sourceModule` — text: 'car' | 'insurance' | 'electronics'
- `sourceEntityId` — text (the car/policy/electronic item ID)
- `sourceField` — text (which deadline field: 'motDueDate', 'expiryDate', etc.)
- `deadlineDate` — date (the actual deadline)
- `suggestedTitle` — text (the smart-rewritten task title, D-06)
- `suggestedNotes` — text nullable (context about the suggestion)
- `suggestedOwnerId` — text nullable FK to household_members.id
- `status` — text: 'pending' | 'accepted' | 'dismissed' (default 'pending')
- `acceptedTaskId` — text nullable FK to tasks.id (set when accepted)
- `dismissedAt` — timestamp nullable
- `createdAt` — timestamp (default now)
- `updatedAt` — timestamp (default now)

Add index on `(householdId, status)` for dashboard queries.
Add unique constraint on `(householdId, sourceModule, sourceEntityId, sourceField, deadlineDate)` to prevent duplicate suggestions for the same deadline.

### 2. Create migration
**Run:** `npx drizzle-kit generate` to generate the SQL migration.
**Run:** Apply migration to Supabase.

### 3. Add RLS policy
Allow household members to read/update suggestions for their own household.
